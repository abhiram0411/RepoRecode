## Browser workspace

Development mode excludes QuickJS and its WASM variants from dependency prebundling so relative binary URLs retain their module location. TypeScript, parse5 and css-tree are prepared eagerly; discovering worker-only parsers on first preview would otherwise trigger a full-page development reload. CI checks development-mode practice and previews separately from the production suite.

The React SPA owns navigation, source study, Monaco editing, a static relationship graph and accessibility. Source import accepts a narrow source allowlist and bounded archives. A reusable worker builds a virtual TypeScript compiler host. It caches only the most recent source snapshot, compares exact content and reparses changed/new files. Declaration, fact and call indexes are reused for files unaffected by changes. Invalidation follows both old and new import/reexport/type-import dependency graphs, including removed targets and new resolution candidates. Global scripts, namespace/ambient augmentations and truncated fact lists conservatively force full reanalysis. The compiler binding program, state relationships and API candidates are rebuilt each request. Cached results are copied so caller mutation cannot poison future analysis. Graph references use one traversal per file and direct declaration lookup. The cache is cleared on worker failure, a 20-second parent deadline, project deletion or application unmount; overlapping requests are rejected. No compiler cache is persisted. Identical snapshot hashes resume existing progress before analysis; changed snapshots remain separate projects. AST declarations carry exact offsets and line ranges. Compiler symbol resolution supplies local call and JSX component edges; unresolved and dynamic relationships are omitted.

The index also records syntactic variables, state hook calls, HTTP calls, error handling, tests and entry points. Router, database and authentication candidates remain explicitly uncertain. These facts are not runtime traces.

The state relationship index resolves const tuple bindings from imported React useState/useReducer declarations through the compiler checker. It links direct reads, updater calls, initializer references and JSX prop references back to the originating hook. Bounded provenance also follows two const initializer steps in the same function, preserving intermediate source locations. It considers at most 200 candidate bindings and eight distinct paths per binding; expressions are bounded to 128 nodes/depth 12. Calls, property access, mutation, closures, shadowed names, type-only references and non-React hooks are excluded from propagation. These are lexical dependencies, not computed values, callback delivery or execution order. The list caps at 200 distinct relationships with an omitted count; the diagram displays the first 60. Analysis version 9 triggers safe refresh for older snapshots.

Roadmaps follow actual call dependencies and adapt wording to experience and goals. Source explanations, hints and quizzes are deterministic and derive from indexed source facts, selected symbols, diagnostics and evaluation results. No external AI provider is used. The Coding Pet only reacts visually; it supplies no explanations.

The API path index connects literal root-relative fetch requests to declaration-resolved Express app/Router routes when method and path match exactly. Every connection is labelled a candidate: origins, router mounts, middleware, dynamic paths and actual delivery are not inferred. Shadowed fetch names, type-only/fake Express imports and ambiguous request methods are excluded. Limits are 200 combined sites, 200 candidate links and 60 diagram nodes. The source list and graph open the containing declaration, or a highlighted read-only source excerpt for top-level sites. Imported requests are never sent by this index.

## Evaluation and preview

A supported function passes a limited type environment before transpilation. The original and candidate execute in fresh QuickJS runtimes for each bounded probe. Sampling varies every parameter before filling the 64-case budget. References run twice; observed instability or unsupported output makes grading unavailable. Failed reference inputs are excluded and counted visibly; exception behavior is not graded. Typed output keys distinguish missing/undefined/null and nonfinite values, preserve array order and ignore plain-object field insertion order. Callable/cyclic outputs are rejected. Zero valid reference probes cannot pass. Mutated debugging and missing-code challenges require a passing reference and failing mutation.

Feature missions transform each finite numeric reference output by a stated rule. They record separate completion and do not incorrectly mark the original contract complete. Independent missions unlock after passing the original function. Interviews save self-explanations without an automatic correctness claim.

React preview offers initial SSR and a persistent interactive reconciler inside QuickJS. Source JSX receives file and line attributes. A source patch handles exported function and arrow declarations without modifying imported files, and maps shifted lines back to the original snapshot. parse5 rebuilds output through tag, attribute and style allowlists. A script-disabled iframe displays sanitized HTML. Parent inspection validates locations against the source index.

Plain CSS files are included within the source import limits. The VM records side-effect stylesheet imports in execution order; only those imported paths are accepted. CSS-tree reconstructs allowed selectors, declarations, explicit & nested selectors and media blocks up to four combined levels. Declaration order is preserved without expanding selector combinations. URL/raw nodes, arbitrary functions, external imports/fonts, pseudo-elements, implicit nesting/raw parser recovery and animation constructs are omitted. Variables cannot carry URL nodes; generated CSS escapes HTML closing delimiters. Inline styles use the same declaration allowlist. Loaded CSS is capped at 256 KiB, each stylesheet at 128 KiB, 20,000 AST nodes, 1,000 rules and 3,000 declarations. Parser work stays in disposable workers with parent deadlines. Default imports from local .module.css files expose a frozen null-prototype mapping of up to 200 class/ID names, each at most 100 characters. Accepted selectors are scoped by the immutable snapshot file index, including nested selectors. Bootstrap prepares export mappings and raises module preparation errors only when loaded; the collector sanitizes loaded styles and reuses them for later interactions. Composition, global module selectors and @value are omitted with notices; bound plain CSS and named/namespace CSS imports fail explicitly. Name scoping separates module selectors, not security domains within the same imported preview. Styling is display-only and does not become visual-equivalence grading.

Interactive sessions use a VM-local scheduler, React 19.3.0 and reconciler 0.34.0, pinned for compatibility. Parent-side input/click/change/submit listeners send plain bounded event data to a serialized worker protocol. Each session has a 48 MiB heap, 1 MiB stack, 1.5-second mount and 750-ms action deadline, plus parent deadlines (15 seconds mount/5 seconds action). Queues stop at 20 pending actions; sessions stop at 200 interactions. Source/props changes or unmount terminate the worker. Errors preserve the last good HTML and require a new render. Form submission runs in the VM without enabling forms or scripts in the iframe. DOM refs, browser APIs, timers and asynchronous handlers remain unsupported.

The TypeScript transform also records imported function entries, preserving directive prologues and expression-arrow returns. Traces keep 100 calls per render/action with an omitted count; locations are checked against original source bounds before display and linked to the narrowest indexed symbol. Event history keeps the latest 20 deliveries and whether sanitized HTML changed. This untrusted local observation is for learning, never authorization or mastery; arbitrary imported code can interfere with its own execution and observations.

Resolved direct React useState/useReducer imports receive a transparent return-value observer. Aliases and namespace/default imports are supported; shadowed names are excluded. Up to 100 state reads per action retain render order with bounded local value summaries. Inspection avoids getters and toJSON, with all work inside VM limits. There is no instance identity, final inventory, before/after diff, full call stack or network trace.

## Device storage

IndexedDB reporecode version 1 has projects keyed by UUID and settings keyed by preferences. Project records contain files, index, lessons, attempts, drafts, completed symbols, prediction evidence, feature missions and interview notes. Maximum 25 projects, bounded source and payload size. Drafts debounce after edits. Backups rebuild the source index and discard invalid symbol references. Preferences also use a validated synchronous localStorage copy so immediate reload cannot interrupt the ordinary IndexedDB save. Invalid/unavailable copies fall back to IndexedDB. No AI lesson payload or provider request is required.

Analysis versions allow older saved projects to refresh derived symbols/lessons without replacing source or learning data. The transaction rereads the latest project, rejects deletion or changed source, and preserves concurrent drafts/notes. Function probes support scalar unions, nullable/optional/default values, scalar arrays, small fixed tuples and inline objects while preserving undefined/omitted distinctions. Objects allow two object levels, three total scalar leaves and 16 samples; number/string fields use four representative values and other scalar unions must fit four choices. Omitted fields and own undefined properties are distinct; computed literal encoding handles quoted and __proto__ keys without prototype mutation. Methods, computed declarations, index signatures, deeper shapes, array-valued fields and wider unions are rejected. Typed prediction keys retain the same distinctions; compound outputs that cannot be faithfully entered as JSON are excluded. Optional device-theme following subscribes to media changes without writing a preference on every OS change; choosing a manual palette disables following.

A SHA256 of canonical sorted source detects identical snapshots. Offsets are stable within a snapshot, not across code versions. New source versions have independent progress. Explicit cloud restoration merges identical snapshots without replacing local drafts/notes and keeps changed-source conflicts as separate copies. Atomic IndexedDB writes detect concurrent changes and reject the whole batch on failure. Live provider acceptance is pending; there is no automatic background sync.

## Gateway and operations

The Node gateway verifies bearer identity through Supabase, validates exact request origins, bounds schemas, and allows at most two concurrent protected operations. Historical tutor/provider routes return 410; no external AI request path is active. Optional local Ollama is not implemented.

GitHub App authorization uses shared one-time state and PKCE. Database transactions serialize begin/consume/complete/disconnect by owner; state is hashed, expires after ten minutes, and is superseded by a newer connection attempt. Access and refresh tokens are encrypted with AES256-GCM using a server-only key. Expiring access tokens rotate under a 60-second database lease; conditional updates compare previous ciphertext and lease identity, so disconnect/reconnection wins over stale refresh results. Waiting callers reread persisted credentials with a bounded retry budget. A crash after provider rotation but before storage may require reconnection. Access is limited by the user's and installed App's grants. Imports pin a commit and use fixed API endpoints with per-call and overall deadlines.

The admin API checks trusted app metadata and MFA assurance on every call. It reports actual process metrics and optional database aggregates. CPU, memory and billed cost are unavailable rather than invented. Alert delivery is disabled until explicit destinations are configured. Persistent state deduplicates active/recovery transitions. A separate hosted watchdog detects outages after three failures.

## Deployment and scaling boundaries

Static assets can be served by a CDN. Analysis and sandbox work consume each visitor's browser resources rather than arbitrary server processes. Cloud data is accessed through pooled Supabase APIs. GitHub state and token leases are shared in PostgreSQL; local feedback, process telemetry and request limits still target one gateway replica. Historical AI quota rows are inactive. No infrastructure spending is authorized.

There is no hosted queue for large imports, OS-level cloud execution sandbox, complete runtime flow collector, distributed incident store or infrastructure billing adapter. These are explicit remaining production work.

Interactive sessions snapshot CSS text and cache sanitized output per loaded file. Every collection still validates imported paths, source order and total size before use. Unloaded files are not parsed. Disposal clears the cache; another source snapshot never shares it. A static startup message and reload link remain readable if the application module does not load, with a separate no-JavaScript explanation.


Practice now resolves small interface inheritance trees, including renamed imports/reexports, multiple distinct bases, optional and readonly inherited fields. Duplicate/overridden fields, diamond duplicates, cycles, merged declarations, dependent/object-constrained generic, qualified or non-interface bases and oversized/deep shapes remain unsupported. Existing bounds remain: depth 8, 256 expansion visits, three properties per object, two object levels/three leaves, 16 object samples and 64 probes. Analysis version 10 refreshes old indexes.

Concrete generic practice supports aliases and interfaces with up to three unconstrained type parameters with explicit arguments or bounded defaults, including instantiated interface bases. Type arguments must expand into existing bounded input shapes. Generic functions, constrained type parameters, conditional/mapped types and recursive expansion remain unsupported. Read-only input type context preserves generic names and readonly fields.

Function grading now settles native QuickJS promises and async/await results, with at most 1,000 microtask jobs and the existing 75 ms, 8 MiB and stack limits per probe. Promise chains, resolve/reject/catch and homogeneous Promise.all inputs work in the limited type environment. Timers, network and external dependencies remain unavailable. Pending reference promises make grading unsupported; rejected reference inputs are counted as excluded exception coverage. Grading compares settled outputs, not event-loop ordering or promise identity.

Default generic arguments resolve in declaration scope, including defaults referring to earlier parameters and defaults on inherited/imported interfaces. The read-only type context preserves defaults with imported type names expanded locally. Missing required arguments, forward/self references, invalid required-after-default ordering and shapes outside the existing bounds remain unsupported. Local continuation adds independent scalar constraints (number/string/boolean, null/undefined and bounded literal unions), validates concrete arguments and defaults, and preserves extends clauses in the isolated type context. Dependent/object constraints and unresolved constrained wrappers remain unsupported; finite probes do not establish general generic correctness. This continuation is not deployed.
